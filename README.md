## 斗地主候选保存失败修复（2026-10-07）

实机已出现有效事务 320 条、来源 19 局，但训练报告「候选保存失败；稳定模型未改变」。原因定位在 localStorage 写入失败，而非训练局数不足；旧实现未暴露具体底层错误。

候选、活动版及回滚版改由独立 IndexedDB 保存，事务完成后才确认成功，活动版和上一版同一事务更新；模块加载时恢复数据库版本，兼容读取原 localStorage 存档。保存成功后只移除已被数据库替代的本拓展模型副本，保留训练样本和其他数据。数据库不存在时仍兼容旧存储，数据库实际报错则保留旧版并显示错误。

训练区直接显示上次失败原因与保存后端，关闭重开面板也能看到原因。新增事务完成、写入失败、回滚、重载恢复与小容量存储写满回归；浏览器验收使用独立测试数据库。

## 本地调试：决策分析日志

在扩展设置的「战报/日志 → 测试决策日志」中选择「摘要」或「详细」。修改扩展源码后，需要重载游戏以载入新模块。

- **推荐动作与综合评分**：引擎此次选出的候选建议；评分用于比较候选，不是胜率，实际出牌还受后续执行裁定影响。
- **备选动作与分差**：与推荐动作比较的另一个候选，以及两者的评分差。
- **当前策略与武将打法**：分别说明本次的战略目标、行动意图，以及从技能语义归纳的打法，例如「击败地主 / 集火」「资源型」。
- **推荐原因**：说明目标评分、预期收益、增量收益和连招规划评分等依据。不同评分项含义不同，不宜直接相互比较。
- **参考分歧**：规则评分推荐的动作类别与小模型分类倾向不同。模型分类置信度不是胜率，也不是对某张具体牌的推荐；此日志用于复盘，分歧本身不会触发模型接管。

摘要按行显示，详细模式补充候选、收益维度、规划与性能信号。同一次分析作为一块日志输出，避免段落顺序倒置。关闭决策分析后，内部回放仍保留，其他诊断提示仍可能出现。

### 回合汇总与战报口径

角色回合结束显示观测动作数（宿主出牌、响应、技能日志）和匹配提交后的引擎分析数。两者不是一一对应；「无匹配分析」不等于 AI 未运行。额外回合独立计数，终局未完成的回合标为中断。关闭测试决策日志会同时关闭回合汇总，内部统计继续累计。

战报区分整局累计计数与最近样本：分析日志保留20条，记分日志保留400条，回合汇总保留100个并在战报展示最近12个。分差和精选决策仅代表近期样本，评分差不是实际决策正确率。存活人数分母包含阵亡角色；历史平均是本人的结算积分。

后续对局的归档胜负直接取宿主 `game.over` 结果，无法确认时显示未知，不按积分猜测，也不计作平局。旧归档保持原数据，不将旧的积分推断结果伪装成新获取的真实胜负。归档 JSON 额外包含整局统计、近期回合汇总和全场事务计数，供调试复盘。

验证命令：`node --experimental-vm-modules apps/core/extension/无名AI/tests/gameTelemetry.test.mjs`（从无名杀仓库根目录执行）。该测试验证统计、归档、战报生成与模拟阶段/终局钩子，不代替实机对局验收。

### 训练标签更新保存（本地修复）

结算与异步收益反馈修改标签后，样本重新进入待保存队列。数据库读取保留原自增主键，更新覆盖同一条记录，避免标签回填变成重复样本。保存按事务串行执行，事务完成后才确认版本；写入中再次修改会继续保存，失败保留待保存状态，后续保存可重试。旧数据库无需删除重建。

保存仍使用1秒防抖，尚未处理立即退出时的强制刷新。数据库失败后的本地兜底容量有限；当前不承诺失败后马上退出也能完整恢复。满额导出的保留机制见下一节；手动清空已改为等待数据库与本地备份清理完成，见后文。

验证命令：`node --experimental-vm-modules apps/core/extension/无名AI/tests/trainingPersistence.test.mjs`。覆盖事务提交确认、并发修改、失败重试、重复记录、初始化、结算/异步反馈与模拟重载；实机重启仍需验收。

### 数据库自动重试与保存状态（本地修复）

写入失败后无需新动作，也会按2、5、15秒各自动重试一次；连续失败后暂停，后续动作只继续保存本地兜底，不重置失败预算。训练面板的「样本统计」显示待保存数量、失败原因、下一次重试和暂停状态；「立即重试保存」恢复连接并重新启动有限重试。

数据库打开和读写/批次清理事务均设8秒超时。超时尝试中止事务并释放任务队列，迟到成功不确认已保存；新样本使用固定字符串键，重试覆盖同一条。旧版自增键保持兼容，本地兜底额外携带内部键供恢复，内部键不会进入训练JSONL标签。写入失败或连接失效会重连，重连只恢复连接，不重新加载覆盖当前内存。事务超时仍不能保证设备底层操作立刻停止，持续异常时有限重试后暂停。

验证命令：`node --experimental-vm-modules apps/core/extension/无名AI/tests/trainingSaveRetry.test.mjs`。覆盖退避、暂停、手动恢复、连接失效、超时迟到、固定键、兜底恢复与完整模块状态；实际宿主的异常恢复仍需验收。

### 彻底清空训练样本（本地修复）

设置、训练面板、导出面板、调试接口和模型重置统一等待异步清空结果。先暂停重试并等待旧保存/启动读取收束，再通过串行事务清空 samples 存储和删除本地备份，最后清空内存。数据库不可用、超时或本地删除失败均返回失败，保留内存并重新安排持久化，不提示已经清空。重复请求合并为一次清理。

清空期间暂停新增和导入样本，旧读取/重试/导出通过操作代次隔离，避免迟到回调恢复旧数据或清理新样本。清空成功后可继续采集；resetAll另重置导出计数，冠军旧决策回流等待重置成功后执行。此操作仅清训练缓冲和数据库，不删除已导出的文件、模型权重或对局档案。实际删除仅在用户调用清空入口时发生，代码修改与测试不清理现有用户数据。

验证命令：`node --experimental-vm-modules apps/core/extension/无名AI/tests/trainingClear.test.mjs`。覆盖清空后模拟重启、在途写入/重试、初始读取、重复请求、事务超时/本地删除失败、迟到导出和模型回流顺序；真实宿主清空与重启仍待验收。

### 满额导出与数据保留（本地修复）

训练缓冲满10000条后暂停新增独立样本，允许已有样本继续更新标签。下一次新增请求触发自动导出；同一时间只执行一个自动任务，完成或失败后至少间隔60秒，后续新增请求才会再次尝试。样本统计提供暂停状态、累计暂停数量与最近导出状态。

原生文件导出等待写入返回，能读回时核对完整文本，文件操作8秒超时。只有读回一致才尝试批次清理：保留当前对局、无有效标签、快照后更新及新增的数据；按原数据库主键删除已导出条目，不使用全局清空。清理事务失败或期间发生标签更新时回滚并保留内存样本。JSONL补充计数、置信度、时间及异步反馈标记。

原生接口失败回退浏览器下载；下载只能确认触发，无法确认用户实际保存，因此不清理。缺少读回接口时也保留样本。手动导出等待结果并显示准确状态，但始终保留缓冲数据。自动导出的暂停仅影响训练采集，不停止游戏决策。

验证命令：`node --experimental-vm-modules apps/core/extension/无名AI/tests/trainingExportSafety.test.mjs`。覆盖失败、超时、读回不一致、下载保留、清理回滚、快照后更新、当前局保留、满额暂停与重试节流；原生落盘与实际下载仍需实机验收。

### 真实结果与样本隔离

宿主 `game.over` 的明确结果是结算、反馈、回放与训练的唯一胜负来源，不根据积分或存活判断。只接受胜/负的学习接口跳过平局和未知局；无法取得明确胜方时不按存活玩家分配胜方奖池。

## v3.1β 重点改进

当前版本重点收敛“同一局面只有一套事实解释、同一种最终决策只有一个权威策略”，近期已覆盖：

- **桃救援**：阻止 AI 在敌方/中性角色濒死时错误使用【桃】。
- **铁索连环**：按全局横置状态评估单目标、双目标与重铸，而不是固定选两个目标。
- **无懈可击 / 判定区 / 拆顺逻辑**：加强敌我方向和状态收益的一致性。
- **特殊锦囊**：为借刀杀人、桃园结义、五谷丰登等建立独立 evaluator。
- **状态与关系收敛**：统一 player snapshot、relations 与 action utility，减少多套并行规则。
- **工程稳定性**：完善 hook 生命周期、缓存失效、异常诊断和行为回归测试。

## 当前模型契约

> **FEATURE_DIM = 130；网络 130 → 128（GELU + LayerNorm）→ 64（GELU + LayerNorm）→ 6 标签 + Critic 价值头；权重 Int8（SCALE=128）／偏置 Int16；权重快照 VERSION=7。**

旧 48 / 96 维模型与训练数据与当前契约不兼容，载入时会被版本/维度校验拒收。

## 二、系统架构

### 2.1 整体闭环

```
┌─────────────────────────────────────────────────────────┐
│                    AI 大脑（当前运行形态）                │
├─────────────────────────────────────────────────────────┤
│  感知层：状态 / 关系 / 牌堆 / 身份 / 对手与团队意图      │
│  规则层：候选生成 + 规则评分 + 专项 evaluator             │
│  主策略：Champion Strategy 对同类型候选提权/替换           │
│  模型层：v7 模型用于置信度、校准、训练观测与条件式复核      │
│          （模型未 ready 时 fail-closed，不得影响最终动作） │
│  深思层：deepThink 仅在模型 ready 且满足触发条件时复核     │
│  护栏层：modelGuard 在执行前做最终红线检查                 │
│  学习层：样本记录 / TD value_target / A-B Candidate        │
│  观测层：日志 / 冲突 / 回放 / 对比 / 自检 / Dashboard      │
└─────────────────────────────────────────────────────────┘
```

> 当前代码中，模型逐动作直接加权已关闭（`wModel = 0`），`strategyBus` 的模型仲裁接管也处于停用状态。模型具备合法 v7 权重并处于 ready 状态时，仍可参与置信度、校准与 `deepThink` 条件式复核；未 ready 时由 readiness guard 直接跳过。

### 2.2 决策流程

```
枚举候选动作
    ↓
规则评分 + 专项 evaluator
    ↓
先得到规则 best
    ↓
Champion Strategy（当前主要学习接管层）
    ↓
模型 ready ?
    ├─ 否 → 跳过模型改写
    └─ 是 → 置信度/校准/冲突观测 + deepThink 条件式复核
    ↓
modelGuard 最终护栏
    ↓
输出最终动作
    ↓
记录样本 / 回放 / 诊断
    ↓
局结束 → TD/异步反馈 → Candidate A/B → 持久化与统计
```

## 五、注意事项（必看）

### 5.1 常见坑

| 坑 | 解决方案 |
|---|---|
| 新建模块后忘记在 engine.js 加 import | 挂载代码不执行 → 自检报 undefined |
| 用 ui.create.dialog 打开面板 | 内容区空白 → 改用全屏遮罩 |
| 静态 import 导致整个 extension.js 加载失败 | 改成在 engine.js 显式 import |
| node --check 抓不到 ESM 顶层裸 return | 用 `node --input-type=module --check < file` |
| 硬拦截 useCard 返回 null 会导致游戏崩溃 | 改成仅日志不拦截 |
| 控制台不支持 console.table | 用纯文本字符串拼接 |
| `window.__DJSC={...}` 直接赋值覆盖其他模块 | 必须用 `Object.assign` 或 `|| {}` |

### 5.2 性能注意

| 项 | 说明 |
|---|---|
| 特征提取 | 每次决策都跑，必须 O(n) 复杂度 |
| 元认知计算 | 轻量，不超过 1ms |
| 校准器观察 | 1500ms 延迟，不阻塞决策 |
| 热更新训练 | 后台异步，不阻塞游戏 |
| 持久化读写 | 统一走中央 storage 抽象；大对象使用配额安全写入 |
| 面板渲染 | 大数据量用虚拟滚动 |

### 5.3 数据持久化

| Key | 内容 | 上限 |
|---|---|---|
| djsc_weights_v3 | 模型权重 | 固定 |
| djsc_element_shadow_v1 | 元素影子表 | 自动清理 |
| djsc_metacog_v1 | 元认知数据 | 自动清理 |
| djsc_calibrator_v1 | 校准器偏移 | 累计 ≤ 0.3 |

### 5.4 兼容性

| 项 | 说明 |
|---|---|
| 130维特征（当前） | 旧 48/96 维模型与训练数据均不兼容，载入会被维度/版本校验拒收；需清空旧数据 |
