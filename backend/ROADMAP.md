# 后端训练闭环长期方案

## 目标与边界

把当前“客户端采样、HTTP 接收、小时归档、内存合并池”逐步升级为可追溯、可复现、可回滚的训练闭环。游戏内仍由客户端完成特征提取和实时决策；服务端负责可靠接收、样本审查、数据集构建、离线训练、评估和候选版本管理。上传与训练隔离，训练任务不得占用接收请求的热路径。

```text
客户端采样与本地持久化
        │ 带版本的批次 + 幂等键
        ▼
接收 API ──► 不可变原始归档
        │             │
        │             ▼
        └──────► 校验 / 去重 / 标签审查
                         │
                         ▼
                  版本化数据集快照
                         │
                         ▼
                 隔离的离线训练任务
                         │
                         ▼
             基线对比 / 整局留出评估
                         │
                         ▼
             候选注册表 → 影子 → 小流量试用
                         │                 │
                         └────失败则回滚 ◄─┘
```

## 数据契约

- 每个批次有稳定的 `batchId`、客户端构建号、样本 schema 版本和特征维度；同一个 `batchId` 重试只产生一次归档与一次下游处理。
- 原始归档只追加，不在接收时改写标签。任何清洗、去重、资格判定都写为带规则版本的处理结果，保留拒绝原因和来源。
- 分开统计 `received`、`archived`、`deduplicated`、`labelled`、`trainable`。进入合并池不代表训练合格；训练资格必须校验已提交动作、观测收益、标签血缘、模式/规则、特征维度和事务唯一性。
- 数据集快照记录样本清单摘要、资格规则版本、训练/验证分局清单和构建时间。相同快照与配置应能复现同一训练评估。
- 服务端模型产物携带特征 schema、标签策略、训练快照、代码版本和评估报告；前端只接收契约匹配且通过门禁的候选。

## 分阶段实施

### 阶段 0：接收可观测性（本轮）

新增 `ingest-receipt-v1`：客户端可看到批次归档、合并池新增、样本去重和未标记结果数量；同进程内响应丢失后的重试复用原回执。补 HTTP 契约测试、前端兼容旧服务的解析器和 CI 检查。这个阶段不宣称训练资格，也不改变训练权重或默认采集行为。

### 阶段 1：可靠存储与幂等

将进程内请求去重和状态迁到持久存储，选型前基于实际部署盘、备份和并发评估。小规模单机可先用 SQLite 元数据与追加归档；只有观测到单机写入/并发瓶颈后再拆 PostgreSQL、对象存储或队列。要求崩溃恢复、唯一键约束、备份恢复演练和有界保留策略。

### 阶段 2：质量审查与前端闭环

把客户端 `modeDataset` / `labelPolicy` 的资格规则整理成有版本的服务端审查契约；逐类比对客户端与服务端结果，差异可追踪。回执增加审查版本、可训练样本数和拒绝原因汇总。前端提供按最近对局的“采集→执行→收益确认→标签有效→最终合格”漏斗，避免只显示最终的零而无法定位断点。

### 阶段 3：可复现数据集

从不可变归档构建分区数据集；按整局隔离训练/验证，排除跨集 session 泄漏和冲突事务。每个训练任务固定数据集快照、标签政策、特征 schema 和随机种子；输出按模式、角色、规则分组的审计报告。

### 阶段 4：离线训练与发布门禁

训练运行器独立部署并有 CPU、内存、时长和并发限额。候选与公共基线、当前试用版本在相同留出局上比较；验证集不足、某角色退化、契约不符或数据审计失败时拒绝晋级。保留完整模型文件、日志、指标和输入快照 ID。

### 阶段 5：模型交付与线上反馈

候选先以影子方式记录预测，再由用户启用小范围试用；按客户端构建、特征版本、规则和模型版本统计延迟、异常、参与率及实战结果。任何契约不匹配或质量退化都回退到已知稳定版本。训练结论与线上表现分开呈现，离线指标不当作胜率提升证明。

## 运维与验收指标

- 接收：收到、成功归档、重试、重复、限流、解析失败和端到端延迟分开统计；批次成功但回执缺失要显式显示为未知。
- 数据：各阶段样本数守恒；拒绝原因有版本和数量；同一幂等键不得重复归档；备份可实际恢复。
- 训练：每次任务可定位代码、配置和数据集快照；整局验证集无泄漏；训练失败时不覆盖当前稳定模型。
- 前端：上传回执、训练漏斗、候选状态和当前生效版本使用同一套版本标识；训练不阻塞出牌与响应。
- 上线前先从现有 8787 服务采集容量、延迟、归档增长和恢复时间基线，再定数值型 SLO；本仓库当前没有经核验的线上容量基准。

## 当前已知限制

仓库中的 `backend/server.py` 是标准库 HTTP 接收器，去重状态与合并池索引仍以内存为主；它不是训练服务。`merged_samples` 的标签字段检查只是候选过滤，不能替代 `sampleEligibility.js`、`labelPolicy.js` 和 `modeDataset.js` 的完整训练资格检查。本轮回执缓存也只在进程存活期间有效。当前客户端目标为 `https://data.feiqiaoai.uno/`，实际代理、服务进程和数据盘位置需在部署环境核对后才能设计持久存储迁移。
