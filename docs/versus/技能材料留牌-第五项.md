# 2v2 技能材料与明确付费的留牌：第五项

[weique | 2026-10-20] 本地候选实现，真实2v2宿主及联机尚未验证。只处理当前清单的第一项，不同时修改斩杀、替补或额外回合逻辑。

## 实际接入位置

宿主选中 viewAs / 主动选牌技能后，ai.basic.chooseCard 会改用技能的 check 再递归挑选材料。普通 cardConsumption 只处理卡牌候选，无法覆盖这次实际材料选择。

新增 materialReserve.js 在实际 ai.basic.chooseCard 调用处包裹本次评分函数，不修改 lib.skill 的全局 check、过滤器、合法性、技能用途或真实结果。engine 安装 / 卸载该桥；新局、结束、窗口变化和卸载后旧回调失效。

覆盖范围：

- 自己正式出牌窗口中，已选技能具有明确 filterCard 的静态转化，例如武圣 / 龙胆式单材料、丈八式多材料。
- 制衡式主动技能的原生选牌阶段。
- 宿主 chooseButton 已生成、通过 sourceSkill 指向主动技能且用途已静态确定的 backup；不自行执行 backup 或动态 viewAs。
- 明确主动技能链中的 chooseToDiscard 付费。
- chooseCard / chooseCardTarget 只有明确标记 discard=true 或 lose=true 时才作为付费；普通展示、选择不猜成消耗。

不枚举他人手牌，不运行技能内容或额外调用 filterCard 来探测代价。实际合法候选和应选数量继续由宿主决定。

## 材料偏好

复用已实现的公开座次、队友血线和攻击可达性判断，读取当前行动者自己的手牌。符合危险条件时，最后一张桃 / 闪 / 无懈作为材料的原生评分减2，表达额外保留压力；不重复计算整张牌价，也不加不可选择标记。

例如：1号自己三血，4号队友一血且行动前有公开可达威胁。最后一张桃与普通材料原生评分都为4时，新材料分为2与4；如果用桃发动技能的原生收益分为10，仍可保留8分，不强制禁止消耗。

2号后面紧接队友3号时，不凭3号低血量虚构行动前威胁。闪只按自己防御需要判断，不能当作可救队友的牌。

多材料考虑当前已选集合：两张桃尚可留一张时不全都保护；若第二张也要选走，才补上最后一张的压力。宿主最终重新检查所有已选牌时，同名资源只让最后选入的一张承担这笔压力，不把两张都当作“最后一张”。取消选择、血量、手牌或座次变化后即时重读。

## 响应与必要完成

- 出闪、南蛮 / 决斗 / 借刀响应、无懈、濒死及救援不进入这条主动材料桥；仍由既有响应与救援判断负责。
- 一血时普通桃转杀仍属于消耗救援机会，应考虑保留；但转成桃自疗，或宿主明确声明 recover 标签的回复技能，不因材料压力挡住当前自救机会。
- 对已经提交、必须完成的主动付费，新增扣分最多为原正分的一半，保留正分，不改 forced、filterOk 或原生选牌数量。
- 普通用牌无技能材料、普通弃牌阶段不进入本桥；已有 cardConsumption 和 versusDiscardPremium 不再被本桥追加一份。
- 本机手动、远端玩家以及非普通2v2模式不接管；遵守 tacticalOptimization 开关。

## 尚未覆盖的复杂情形

动态 viewAs 在当前材料阶段仍是函数、临时技能来源未知、纯展示后在内容内部自行决定失牌、任意触发技能或其他回合代价等保留宿主回退，不凭文字推断。自己手牌之外的技能专属牌堆 / 特殊区资源也未纳入“最后一张手牌”的计数。

抽象技能候选产生时尚未确定具体交哪张牌，本项不虚构一份全技能通用代价。先发动再付费、不能撤销的技能，本项只改善实际材料排序，不回滚已经发动的技能。因此本项覆盖常见和明确的材料入口，不代表所有自定义技能的完整成本规划已实现。
