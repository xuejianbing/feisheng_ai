# 斗地主无懈与借刀修复（2026-10-25）

修复关闭 AI 响应、切回手动或换局后，AI 仍沿用旧无懈判断的问题。关闭“无懈优化”时，也会按当前局面重新判断是否出牌。

同时处理借刀通过技能出杀时的选牌问题，以及停用扩展后部分选牌辅助仍然生效的情况。原有设置不用重新配置，之前的手动配合调整继续保留。

下面是开发记录，供查代码和复核测试时使用。

## 本轮修复

1. **优化无懈的旧回调退出。** 原桥接只在创建请求时检查开关与控制权，已创建回调在关闭 responseAI、转手动、请求结束、换局、切换模式或卸载后仍可能返回优化评分。现在每次评分重新检查，失效时原样调用原生 ai1，保留 this、参数、返回值和异常语义。
2. **旧版无懈不保存旧决定。** 无懈专项关闭后的旧桥也保存了初次 use 结论。现在共用生命周期校验，重新计算当前收益和反无懈状态，同时重新经过原有响应执行网关；关闭响应接管或硬接管后不继续覆盖原生评分。
3. **绑定真实宿主窗口。** Player.chooseToUse 会把参数复制进新的 GameEvent；只检查原请求的 finished 会漏掉真正窗口已经结束。两条无懈路径现在绑定实际返回事件，读取该事件当前的 state／info_map，原请求、实际窗口、响应者、局次及模式共同决定是否有效；创建宿主窗口失败后也不能遗留有效回调。
4. **借刀技能材料阶段不跨局续用。** 技能选材料会从 ai1 切换到 skill.check，本轮给已经捕获的材料回调增加同样的窗口／局次校验。换局、结束、模式改变、关闭响应、转手动或卸载后回原检查函数；不重写技能或宿主过滤器。
5. **卸载清理完整执行。** use.js 的卸载函数仍引用迁移后已删除的 DEGRADED，抛错会中止后面的五谷、掉血与借刀辅助桥卸载。改用统一 Execution Gateway 的 clearExecutionDegrade('use')，完整清理辅助桥。主 chooseToUse 包装按所有权恢复，保留后安装的第三方包装器；旧包装器失效，重装不会复活旧回调。

## 保留的行为

- 真实手动火攻自己、友方决斗、铁索、拆白银与 AOE 配合沿用 PR #8 的凭据规则；强制自火攻仍按普通收益处理。
- 配合策略的经典斗地主范围不扩大，原有跨模式兵乐救援继续工作。
- 无懈专项开关仍按本局设置快照工作，responseAI 按原有实时规则检查；两条路径切换后旧窗口退出，新的请求走新路径。
- 不把未知上下文当作必须出牌，不绕过原生合法性或改写宿主最终选择结果。
