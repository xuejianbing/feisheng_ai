# 斗地主配合判断修复

调整队友的无懈判断，减少误打断玩家手动配合的情况。正常出牌、技能强制用牌和托管会分别处理，原有设置继续有效。

这次配合调整用于休闲、开黑和欢乐斗地主。其他玩法保留原来的处理方式。

这次修改参考了 [GitHub 上的两条反馈](https://github.com/xuejianbing/feisheng_ai/pull/6#issuecomment-6294594034)。下面保留开发记录，方便查阅具体实现和测试。

## 一、玩家主动意图的凭据

- `trickUseEvidence` 区分有效手动、有效非手动、未知。只接受当前局次、尚未结束、来源和原目标匹配的真实 `useCard` 记录。
- 无懈不再根据当前人类控制状态直接授予自伤豁免。疑似玩家自伤而凭据未知时，返回 unresolved；响应桥不改原生 ai1，已安装回调中凭据失效也回到原生评分。
- 已确认的托管、强制用牌仍走普通收益判断；普通敌方进攻无需额外意图凭据。
- 控制状态在实际出牌时捕获，随后切换托管不改写已捕获事实。联机连接状态不等于手动控制，明确排除 isAuto、疯狂及本机非本人控制。
- 维持已验证的手动配合、反无懈方向及 AOE 必要保护。不修改设置按钮、默认值、保存值或模型权重。

验证：`node tools/test-wuxie-player-intent.mjs` 20 项通过；`node tools/test-trick-cooperation.mjs` 25 项通过。完整回归与宿主结果见下文。

## 二、新增策略范围与原有优化

统一使用 `cooperationPolicyEnabled()`，复用模式模块的 `CLASSIC_SUBMODES`、轻量模式读取和 `classicEnabled()`，不另建模式快照或设置项。仅在经典斗地主（休闲 normal、开黑 kaihei、欢乐 huanle）且现有经典斗地主功能启用时生效。未知模式／子模式、兵临城下、智斗三国及其他玩法退出新增策略。

| 内容 | 生效范围与回退 |
| --- | --- |
| 手动锦囊配合与无凭据自伤回退 | 经典斗地主；实际响应仍遵守已有响应接管规则；不以无懈专项开关关闭为由恢复旧的人类控制兜底 |
| 借刀组合估值、原生目标桥、实际响应、连招及组合护栏权限 | 同一个经典斗地主范围，另受已有打法优化总开关限制；响应还受 responseAI 控制 |
| 友方拆顺的共享收益计划与新增白银回血权限 | 同一个经典斗地主范围，仍使用原有打法总开关、拆顺和救判定开关；评分与最终护栏采用同一范围 |
| 原有跨模式兵乐救援 | 保留旧战术计划、合法性和开关；范围外不使用新增共享计划改写关系判断及模型护栏 |
| 建议融合 | 原本已有经典斗地主范围，本次不重写融合算法 |
| 缓存／选择窗口／响应材料／决斗点数等基础纠错 | 保持通用，不加斗地主模式限制；增加跨模式缓存失效回归 |
| 桃园、无中、五谷及延时状态估值 | 使用宿主效果、公开牌池和原有延时专项条件，不引入地主／农民假设，保留通用修复 |
| 诊断 | 仍使用已有诊断开关，不新增按钮 |

桥接既检查安装时的范围，也在实际评分时重查；旧回调在模式改变、换局或卸载后回退原生。范围外新建借刀窗口保持原有 ai1/ai2 引用，避免包上一个实际上不应参与的策略。组合护栏必须重验绑定的持刀者与被杀者，不能单凭 `use: true` 元数据放行；forced 击杀职责仍优先。

设置名称、数量、默认值、保存配置、版本号和模型权重均未改动。专项设置仍按原有规则在下一局捕获，经典斗地主功能启用条件复用现有模式上下文。

## 验证

- 19 组 Node 工具全部通过：18 组带编号检查共 1037 项，另 1 组为客户端上报回执契约检查。包含新增 16 项模式矩阵检查，以及更新后的 20 项自伤意图检查、13 项状态指纹检查。材料穷举只计入所属检查项，不额外膨胀数量。
- 无名杀 1.11.6 完整宿主：6 个固定结算场景通过，涵盖低点数杀的决斗、武圣／龙胆／丈八借刀响应、拆白银及公开五谷牌池。
- 同版本完整宿主：11 个行为场景通过，其中 9 个为浏览器真实手动点击、1 个为技能事件内直接自火攻、1 个为指定敌方进攻。正常自火攻在无懈专项开／关时均保留；强制自火攻不获得主动配合权限，队友实际出无懈保护。宿主脚本异常为 0。
- 其他模式验证使用生产模块与宿主桩，检查原生回调引用／返回值、目标计划、关系评分、护栏和旧救援；没有据此宣称各模式完整实战验收。真实双客户端联机、远端断线／托管切换、移动端和胜率未验证。本轮未重跑完整随机托管对局或 Python 测试。
- `git diff --check` 通过。
