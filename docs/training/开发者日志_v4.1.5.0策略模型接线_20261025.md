v4.1.4.0 交付了 v3 蒸馏学生（`client_policy_model_v3.js`，51KB，MLP 114→32→17）但**未接入引擎**（P0 日志明确记录）。本轮把它以影子模式接入：

## 一、为什么是影子模式

v3 权重来自 P0 蒸馏（teacher top1 0.6468，student 对拍一致），但其真实对局域外表现尚未验证；且 v3 只吃 f0-f129（规避动作泄露段），在 134 维客户端下靠前 130 维工作。直接 active 软加分风险不可控，因此：

- **默认 shadow**：每次决策记录模型 top1/top3 与引擎最终槽位的一致性，不改候选分；
- **active 需显式开关 + 影子达标**：`cfg('policyModelV3Mode')==='active'` 且连续影子数据追平/超越基线后才启用（沿用 policyModelV2 的晋级规则）；
- 模型未加载完成时 adapter 自动跳过（skipped++），不阻塞决策主流程。

## 二、接线点

### 2.1 引擎（engine.js）

`bestActionCore` 的 telemetry 阶段（候选已定、护栏 fallback 已应用、决策将提交）：

```js
if (window.__DJSC.policyModelV3 && cfg('policyModelV3Shadow', true)) {
    window.__DJSC.policyModelV3.shadow(eligibleActs, best, null, { mode: game.mode, round: _status.turn.id });
}
```

- `eligibleActs`/`best` 为该决策的真实候选与最终胜出（含 `forcedByRule` 标记），与 v2 adapter 口径一致；
- 无 try 依赖：adapter 内部已捕获异常，引擎侧再包一层 swallow 防拖累主流程。

### 2.2 上报（cloudIngest.js）

- 新增 `collectPolicyShadow()` / `commitPolicyShadow()`：读 `djsc_shadow_v3_pending`（1500 上限），按 decisionId 游标去重（FIFO 2000），单批 200 条；
- 信封字段 `shadowPolicy`，随**首批**上传（与 shadowV5 同策略：首批成功即 commit，不被终批限流拖死）；
- 失败自动重传（游标不推进），服务端按 decisionId 幂等去重。

### 2.3 服务端（server_sharded.py）

信封白名单 `("shadowV5", "shadowPolicy", ...)`，`shadowV5`/`shadowPolicy` 均走 decisionId 去重分支后落盘（SQLite `shadow_ids` + 小时文件）。

### 2.4 维度兼容

v3 `featureKeep` 最大索引 129 → 130 维即可用。适配层 `toModelFeatures` 统一截取前 130 维，130/134/142 维特征均可产出影子记录；<130 维拒绝（不猜）。

## 六、模型热更通道（同轮补）

### 6.1 服务端（零代码改动）

`server_sharded.py` 既有 `/update/` 受限静态路由（仅 `.zip`/`.json`、路径防穿越、`Cache-Control: no-store`）直接可用。新增部署文件：

```
E:\NoNameAI\update\model\manifest.json    # djsc-policy-model-update-v1，modelId=slot17_student_v3
E:\NoNameAI\update\model\policy_v3.json   # {"meta": CLIENT_POLICY_V3_META}，46,821 B
```

清单字段：`modelVersion / releaseSeq / url / sha256 / size / requiresExtension{min:'4.1.5.0'} / schema / classes / featureDim / hidden`。

### 6.2 客户端消费端

- `js/update/policyModelUpdate.js`（新增）：空闲时拉清单 → `classifyPolicyManifest`（unsupported/invalid/needsExtensionUpdate/available/latest）→ releaseSeq 单调 → 下载 → **size + SHA-256 + meta 形状**三重校验 → 写 `djsc_policy_model_v3`。
- `policyModelV3.js` 缓存优先：校验通过的缓存用 `buildModelFromMeta` 纯数据重建（base64→LE float64，relu+softmax），**不执行远端脚本**；失败回退内置 UMD。
- 开关：`cfg('policyModelHotUpdate', true)`；`window.__DJSC.policyModelUpdate.check()/status()` 可手动触发。

### 6.3 工具与验证

- `tools/export-policy-model-json.mjs`：从内置权重导出 JSON + manifest（releaseSeq 自增、打印 SHA-256）。
- `tools/test-policy-model-update.mjs`：22 断言全过（状态机 / meta 校验 / 重建对拍 maxΔ<1e-12 / 下载缓存 / 坏 SHA 拒绝不覆盖）。
- 线上实测：本机与公网 manifest 均 200 + CORS `*`，下载内容 SHA-256 与 size 与清单一致。
- 回归：v3 25 PASS、v2 33 PASS、regressions 94 PASS。
