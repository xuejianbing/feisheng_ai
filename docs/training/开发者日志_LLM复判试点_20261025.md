# 开发者日志 · LLM 复判试点与 134 维重训（2026-10-25）

贡献标识：[weique]　分支：`exp/weights-134-20261025`（已 ff 合入 master，版本 4.1.5.1）

## 一、动机

用户指令：「数据能不能学基础权重」「可以借用我的本地模型」。本轮验证两件事：

1. 用服务端累积数据重训主网权重（134 维），能否超过在架基线；
2. 本地 LLM（qwen2.5:7b，ollama）对局面动作做离线复判，能否作为教师/负样本源。

## 二、134 维重训（train_134.py）

- 数据：merged_shards + ai_shards 全量已结算样本 **304,973 条**（去重后），覆盖 12 种模式；
- 特征：130 维样本补 4 个零 → 134；134 维原样；142 维截断 → 134；
- 切分：按 sessionId 整场留出（1,561 场 / 23,913 条验证），避免同局多步泄漏；
- 配方：教师 512/256 → 蒸馏学生 128/64 + QAT；标签沿用 labelPolicy（action-outcome-v1 一致性校验、vt<0 修正、D/E/F 反例加权）。

### 调参扫描（3 组）

| 变体 | 类权重指数 | 负样本加权 | 选模口径 | top1 | bal | corr | 门 |
|---|---|---|---|---|---|---|---|
| base | 0.75 | 2.0 | corr+0.5bal | 0.4155 | 0.4059 | 0.3788 | hold |
| v1 | 0.5 | 1.5 | corr+0.5bal | 0.4899 | 0.4329 | 0.4247 | hold（top1） |
| **v2** | **0.5** | **1.0** | **acc** | **0.6171** | **0.3678** | **0.4137** | **OK** |
| v3 | 0.75 | 1.0 | 混合(0.6acc+0.2corr+0.2bal) | 0.5586 | 0.3524 | 0.3806 | OK |

基线（在架 v7 权重，134 维原生输入）：top1 0.5500 / bal 0.2756 / corr 0.2181。

**结论**：类权重指数 0.5 + 负样本加权 1.0 + 按 top1 选模 是本轮最优；top1 提升 6.7pt、corr 提升 19.6pt、bal 提升 9.2pt。

## 三、LLM 复判试点（qwen2.5:7b）

### 3.1 首轮教训：泄漏

初版提示词把渲染文本整段喂给模型——其中包含「对局结果: win | 决策价值: +0.12」。
模型直接照着结果打高分（**几乎全部 85 分**），试点无意义。修复：只给「局面 + 动作」，结果字段一律剥离。

### 3.2 修复后结果（n=60，身份场/斗地主/其他各 20）

| 项 | 值 |
|---|---|
| 解析成功率 | 45/60（75%） |
| score vs value_target 相关 | **−0.091（无相关）** |
| verdict 分布 | good 35 / neutral 7 / bad 3（明显偏宽） |
| 身份场子集 | corr 0.6（n=12，样本太少，不足采信） |
| 斗地主子集 | corr −0.409（n=16） |
| 平均耗时 | 0.6s/条 |

### 3.3 判断

- **7B 绝对打分不可用**：偏宽 + 不跟踪动作价值 + JSON 解析率仅 75%；
- 文本输入本身有损（特征为 Int8 量化，手牌只知数量/有无、不知确切组合），限制了 LLM 判断上限；
- 样本中**没有候选集**（`cands` 字段 0 条），因此无法做更可靠的「候选两两比较」。

### 3.4 后续可选路径（按性价比）

1. **客户端补采文本局面 + 候选集**（engine/trainExport 加 `stateText`、`cands`），让 LLM 做候选排序而非绝对打分；
2. 拉 14B/32B 模型（22GB 可跑 Q4）做复判，但需先解决输入有损问题；
3. LLM 只做**错例归因/挖掘**（不需要精确打分），用于标签公式与规则迭代；
4. 主线仍是原生网重训 + 影子/热更，LLM 暂不进入训练信号。
