## 本批实际行为

- 主公和忠臣的硬阵营关系双向一致；反贼互为固定队友，内奸不加入固定队友。自己对自己的 `dispositionOf=0`、`isLikelyAlly=false` 约定保留。
- 身份视图统一返回四角色权重、硬身份来源、可能角色、会话/观察者/私有信息/公开事实/证据/规则版本。无校准数据，界面称“推断权重”。旧 API 继续提供兼容输出。
- 公开身份集中读取。不能通过读取目标 `identity==='mingzhong'` 探测隐藏目标。标准身份场的主公公开；未支持的明忠模式不把暗主公公开。死亡身份仅在 `dieAfter` 且玩家已进入死亡名单后补记，不能在创建 `die` 事件时提前公开。
- 配额只接受宿主身份列表或明确配置列表；删除扩展自行生成经验配额的回退。扣减时保留负槽位，检查人数总量与公开/自身事实冲突；矛盾时报告 `rule-inventory-inconsistent`，保留硬事实，停止配额硬锁。
- 首批支持标准身份场单内或零内。双内、明忠、特殊子模式/未知身份列表不做配额硬锁；不推断未声明的规则语义。非身份模式完整保留旧目标特征语义，避免旧权重收到未经迁移的输入；斗地主标为 `legacy-public-role`，其余标为 `legacy-unreviewed`，未声称已完成公平信息审计。
- 目标特征 `130..133` 改为该观察者合法已知的硬身份；未知全零。自身身份 `12..15` 仍为合法私有信息。维度仍是 134，**但语义发生了变化**。
- 因此身份场的生产 `confidence/safeModelPredict`、冠军偏好及新采样入口暂停，原因 `identity-feature-schema-migration`。低层 `pushSample` 同样拒绝，不能绕过正常采样入口。旧权重文件和历史原始样本保留；没有将它们伪装成新 schema 或新 dataEpoch。
- 身份面板共用观察者视图，不再另用宿主态度猜身份，也不按武将名缓存。关系缓存使用精确版本，公开身份、行为和私有身份的同回合变化立即失效。

## 公开事件与证据旁路

`identityEvidence.js` 保留不可变的公开事件，`eventId` 幂等，相关结果按 `rootActionId + actorId + targetIds` 分组。记录不会因现有 ally/enemy 判断而过滤。保留事件时的公开角色、局面引用、实际公开变化、主动性及拒收原因，不用目标后来公开的身份回写历史。

宿主适配器跟随 `useCardAfter / damageEnd / recoverEnd / dieAfter`，不通过 `then/start/forResult` 主动启动事件。单张酒杀的伤害、用牌完成和死亡属于同根；击杀不单独增加第三份身份倾向。

首批语义包括单目标伤害、实际回复、拆除公开的乐/兵、移除公开装备；强制攻击、AOE 波及、自救和主动性不明的事件仍记录，但不作为主动身份倾向证据。拆顺牌名本身不再在旧观察器中记敌意；未知移牌效果不强行归为伤害。

无懈的语义分类器只有在实际取消了伤害、明确被保护玩家和最终有效施法者时才接收帮助证据。**当前通用宿主钩子尚未完成取消链归因，因此实际无懈回调保守记 `wuxie-final-protection-unknown`。** 合成样本覆盖最终保护及反无懈；不能把这项测试当作完整实战归因已完成。

事件账本本局最多保留 8192 条，超预算明确标记 `event-budget-exceeded` 和 `truncated`，停止收新事件，不静默生成尖峰信念。账本/证据目前旁路运行，不反向调整旧信念分数。

## 信息边界审计结果

已经封闭的直接入口：认知模块中的未公开明忠探测、目标身份 one-hot、训练目标身份元数据、身份面板的宿主态度独立推断、死亡事件创建时提前公开身份。

下列宿主调用仍保留原始语义，**尚不满足整条决策链观察者信息隔离的发布门禁**：

- `score/decision/strategy/tacticalOptimization.js`、`delayedOptimization.js`。
- `js/content/optimization.js`、`precontent.js` 的宿主牌/技能 AI 回退。

这些入口通过显式 `identityDiagnostics` 适配器调用宿主 `effect/damageEffect/attitude`，计数以实际调用为准，标记 `host-semantics-fallback`。没有修改全局宿主函数。计数只覆盖已包裹入口，不等于覆盖宿主内部所有调用。

进一步审计发现的现存旁路，列为后续收敛任务，不声称本批已修复：

- `score/decision/response/wuxieOptimization.js` 的宿主 `damageEffect`。
- `panel.js`、`foundation/io/export.js` 中特权诊断/导出里的真实身份读取；不能将这些诊断数据当作正常信息特征。普通身份矩阵和智能面板已改用统一视图/关系，不消费宿主态度。
- `score/decision/state/playerSnapshot.js` 的 `isLordOf/shaCountOf` 仍有未统一观察者的字段读取；行动级隐藏真值/手牌替换门禁需要覆盖其消费者。
- `score/perception/team/teamBroadcast.js` 的共享意图元数据与跨观察者语义；`playerMemory.js` 的历史身份统计仅可用于赛后分析，不可作为下一局身份先验。

因此本批的隐藏身份替换测试结论仅覆盖统一认知、目标特征、关系缓存和身份面板，不能外推为实际所有候选分/宿主桥接已不受隐藏信息影响。

## 2026-10-18：PR #4 审查补修与真实宿主验证

- 修复 `relations.exposureOf()` 的公开身份来源：身份模式中，`shown`、`known=1` 和 `source` 统一依据 `publicIdentityRole()`。确认在死亡名单中的公开角色返回 `dead_id`，不依赖宿主是否已经设置 `identityShown`；存活主公返回 `shown_lord`，其他存活明置角色返回 `shown_id`。

- 增加死亡公开、公开主公/存活明置角色、濒死未公开三项回归。修改前复现死亡身份被标为 `infer`、公开主公被覆盖为 `shown_id`；修改后身份专项 **44/44**、原配置回归 **94/94**、权重/更新回归 **637/637**，共 **775 项通过**。

真实宿主集成验证使用本机完整无名杀 **1.11.6**，在隔离的 Chrome **155.0.8059.84** 浏览器上下文中正常初始化标准八人身份局，再手动安装生产 `engine.installHooks()`。测试服务器只提供读取宿主文件的接口；没有替换 `Player`、`GameEvent`、卡牌结算、触发器或手动调用证据钩子。为固定输入，初始化后停住自动回合、清理武将技能与手牌，并通过真实选牌/用牌事件执行场景。平时游戏使用的存档和设置不受影响。

四项场景均通过：

1. 普通出杀：经真实 `chooseToUse(type=phase)` 出牌，主公失去 1 点体力；`damageEnd` 与 `useCardAfter` 产生 2 条记录，归为同根、1 组主动伤害证据。
2. 桃救援：杀令主公进入濒死，宿主 `_save` 自然发起 `chooseToUse(type=dying)`，忠臣使用桃使主公回复至 1 点体力；`recoverEnd` 和桃的 `useCardAfter` 正常记录。杀与桃共 4 条记录、2 组证据，根动作分离，桃判为主动帮助。
3. 拆主公的乐：真实过河拆桥移除判定区的乐不思蜀；`useCardAfter` 得到 1 条 `remove` 记录，`removedNegativeJudges=1`、1 组主动帮助证据。
4. 死亡公开：致死杀自然进入死亡流程；`dieAfter`、`damageEnd`、`useCardAfter` 共 3 条同根记录，只形成 1 组伤害证据。目标进入死亡名单，扩展公开身份为 `fan`，暴露状态为 `shown=true, known=1, source=dead_id`。本宿主的该场景中，`dieAfter` 先于 `damageEnd`，账本没有因顺序增加重复证据。

所有场景的 `eventId` 唯一，`duplicates=0`，`truncated=false`，浏览器未报告脚本异常。原始事件、证据分组、角色公开状态和运行版本见 [PR-4-真实宿主验证.json](PR-4-真实宿主验证.json)。
